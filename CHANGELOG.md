## 0.5.0 - 2026-10-09

Commit `b6b4582d2c85`; release record `pub:sha2-256:zabmdlnao5m4relf7pq6s4ctnrf74nudgibggutymvhyesjrwfba`.

### Changed
- pubrel is licensed under Apache-2.0, as publet is, instead of MIT, and the licence text ships as LICENSE.

### Added
- `pubrel withdraw PR|BRANCH` withdraws a release that was cut but never merged: it lists the objects that release added in .draft-discards, which pub never exports, so the next release does not carry them. `prepare` and `check` refuse a release carrying records of another attempt, and `prepare` says what to undo when a release cut again reproduces a withdrawn object.
- `pubrel withdraw PR` refuses an open or merged pull request, and deletes a closed one's release branch from origin and from this clone (unless it is a fork's), so the release can be cut again under the same name.

### Fixed
- `pubrel --help` (and `-h`, `help`) prints the usage to stdout and succeeds; it failed as an unknown command, with the usage on stderr. The usage now lists `summary` among the commands --package applies to, and the --package=NAME and version spellings.
- A version whose part to bump is already u64::MAX is refused with a message, instead of panicking: pubrel's release builds check for overflow, so a pull request could make `check` crash. Found by fuzzing.
- pubrel declared Rust 1.98, the toolchain it is developed with, though it builds on 1.88, the first release with stable `let` chains. It now declares 1.88, and CI builds it there.
- A security check's recorded summary is the last line it printed to stdout. stdout and stderr were joined with stderr last, so a tool that warns on stderr after its summary, as cargo deny does for duplicate crates, had a warning recorded in place of its result. Facts and tool versions are read from stdout first too.

### Internal
- Documentation brought towards pubkit's Rust crate standard by its rust-crate-quality agent: exact `# Errors` sections and docs for every item other modules use, `// covers:` comments on the unit tests, a README covering commands, why pubrel, related tools, versioning and its versioned interface, MSRV and security, and a new SECURITY.md.
- pubrel depends on publet-core 0.1.2 from crates.io instead of a git tag, and its manifest carries crates.io metadata and an include list, so it can be published there. Scenarios cover init, --version and --help.
- What `check` reads from a pull request is fuzzed: release.json, unreleased.json, the corpus lock and the manifests with the version arithmetic. CI runs it on every change.
- pubrel's dependencies are checked in CI and before each release: cargo deny (advisories, licences, sources) and cargo vet (audits imported from Mozilla, Google, the Bytecode Alliance, Zcash, ISRG and Embark Studios, trusted publishers, or exemptions with their evidence). SUPPLY-CHAIN.md ships in the package, and each release records the checks in a signed security claim.
- CI builds pubrel on its minimum Rust version, runs the tests on 32-bit (i686) and big-endian (s390x) targets, and runs nightly, with longer fuzzing and the latest stable and beta Rust.
- `make publish-check` verifies the package in its own target directory: sharing target/ left cargo reporting pubrel up to date after source changes.

### Security checks
- advisories, licences, bans and sources: `cargo deny --locked check --hide-inclusion-graph` (cargo-deny 0.20.2) -- advisories ok, bans ok, licenses ok, sources ok
- supply-chain audits: `cargo vet --locked` (cargo-vet 0.10.2) -- Vetting Succeeded (29 fully audited, 23 exempted)
- supply-chain report current: `./tools/supply-chain-report.py --check pubrel && echo 'SUPPLY-CHAIN.md current'` -- SUPPLY-CHAIN.md current

## 0.4.2 - 2026-10-07

Commit `5ba28c0ecf2f`; release record `pub:sha2-256:s4jum2zqhzjsq3qxyiezd5ux3zl7lck2pf3b2cqso4pdcnlsgnma`.

### Added
- A crate whose release.json entry sets `"semver-checks": true` has its public API checked against its last release by cargo-semver-checks, in `check` and `prepare`: `changed` or `removed` allow a break, `added` an addition, and anything else no change. The release workflow installs the tool when given `semver-checks-version`.

## 0.4.1 - 2026-10-05

Commit `0fb8f054259e`; release record `pub:sha2-256:auupnlfuhd4jls72dsswnrj5534fnsmqlp7vzae6olm4qcp3qpiq`.

### Added
- release.json may declare security checks and facts. prepare runs the checks before releasing, refuses to release if one fails, and records each check's command, tool version and summary, and each fact, as a security claim signed with the release; the changelog and release notes list it, and check and tag refuse a release whose declared record is missing or unsigned.

## 0.4.0 - 2026-10-05

Commit `3997cb69934e`; release record `pub:sha2-256:raxwygjj2zzcymkbhtrh424vrmlmgsdl2efe7zner5wzr3jfv5xq`.

### Changed
- Versions follow Cargo's convention below 1.0.0: changed or removed bumps the minor version (0.3.1 to 0.4.0), and added, fixed or security bumps the patch version. From 1.0.0 the rules are as before. Versions are semver::Version, parsed strictly (no pre-release or build suffix), and the pub this drives must satisfy ^0.1 as Cargo reads it (at least 0.1.0, below 0.2.0).

## 0.3.0 - 2026-10-04

Commit `6173ec3e3a90`; release record `pub:sha2-256:v6wtc2hknnq2x7mprc3ja6sbycantm2c7wx5fx7ampiawapyseka`.

### Added
- release.json may list several `packages` -- a workspace and crates in it released with versions of their own -- each with its own unreleased list, package publet, changelog and tag prefix (`publet-core-v0.1.1`). add, next and prepare take --package; check, changelog and tag act on every package. A workspace bump leaves the pins of independently versioned crates alone, and their own releases pin their new versions in the workspace.
- A sixth change category, `internal`: a code change nothing users run sees (a refactor, a crate moved). It satisfies check, never bumps the version, and is listed in the next release something else makes.

## 0.2.0 - 2026-10-04

Commit `e3d0bcebc4bb`; release record `pub:sha2-256:kcmpa4wxncdzvbzyt7gdpczt25xzoxyvhidda76hchh7ei7ypmea`.

### Added
- check and tag verify that the package publet's identity and release claims carry a valid signature by the key release.json names (`key`, which init now records), and that every object they read hashes to its identifier; without `key` they warn instead.
- next, check, tag and changelog read the package publet in-process with publet-core, so only prepare needs pub. release.yml no longer installs pub (its pub-version input is accepted and ignored) and caches the pubrel it installs by version.
